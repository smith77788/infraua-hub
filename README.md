# Palanter — консоль аналітика

Фронтенд платформи **Palanter**: граф знань з перевіркою онтології, розслідування
з обґрунтуванням, мапа, справи та журнал аудиту — з контролем допуску.

Принцип, який визначає кожен екран: **жодна відповідь системи не є
непідзвітною.** Кожне число обчислює код, який справді виконався; кожен
згенерований висновок перевіряється за первинними фактами перед показом; кожне
читання фільтрується за допуском ще до складання відповіді; кожна дія
потрапляє в журнал, захищений ланцюжком хешів.

This project was built with [Lovable](https://lovable.dev).

## Екрани

| Розділ            | Призначення                                                                                                                                                           |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Огляд**         | Чи можна довіряти системі просто зараз: що є в графі на вашому допуску, чи цілий ланцюжок аудиту, що сталося нещодавно.                                               |
| **Розслідування** | Запит звичайною мовою. Відповідь ніколи не приходить сама — з нею план виконання, знайдені документи, пройдений підграф і обчислення в пісочниці за будь-яким числом. |
| **Граф**          | Усі сутності та звʼязки, дозволені вашим допуском, із інспектором властивостей і походження.                                                                          |
| **Аналіз**        | Хто є посередником між кластерами, які сутності мають ризик і **чому саме**, які записи схожі на дублікати, як повʼязані дві сутності.                                |
| **Мапа**          | Сутності з координатами. Нічого не геокодується і не вгадується — обʼєкт зʼявляється лише якщо його власні дані кажуть, де він.                                       |
| **Справи**        | Тривала одиниця роботи. Класифікація справи піднімається під те, що до неї долучили, і ніколи не опускається.                                                         |
| **Завантаження**  | Вільний текст або структуровані записи. Звʼязки, які відхилила онтологія, показуються, а не зникають мовчки.                                                          |
| **Аудит**         | Ланцюжок хешів, зі станом перевірки на першому місці.                                                                                                                 |

## Що потрібно, щоб консоль ожила

Консоль — це лише інтерфейс. Дані, розслідування та журнал живуть в **API
платформи** ([репозиторій Palanter](https://github.com/smith77788/Palanter),
каталог `apps/platform`), який треба розгорнути окремо: він тримає граф, виконує
код у пісочниці й веде журнал аудиту, тож статичний хостинг його не запустить.

Коли API розгорнуто, вкажіть його адресу змінною середовища:

```
VITE_API_BASE_URL=https://ваш-api.example.com
```

Порожнє значення означає той самий домен. Ще одна необовʼязкова змінна —
`VITE_MAP_STYLE` (стиль MapLibre; типово безключові demo-тайли).

Вхід у консоль — за API-ключем. **Ніде в інтерфейсі не можна обрати собі
рівень допуску**: ключ і є посвідченням, а рівень визначає сервер.

## Розробка

```sh
git clone <адреса-цього-репозиторію>
cd <назва-репозиторію>
bun install
bun run dev
```

Перевірки, які має проходити кожна зміна:

```sh
bunx tsc --noEmit   # типи (tsconfig тут суворий)
bun run lint        # eslint + prettier
bun run build       # клієнт + SSR + nitro
```

## Структура

```
src/routes/          маршрути TanStack Start (_console.* — layout консолі та її екрани)
src/console/views/   вісім екранів
src/console/lib/     типізований клієнт API та форматування
src/console/hooks/   сесія (ключ + допуск, який визначив сервер)
src/console/components/  оболонка, граф на canvas, примітиви інтерфейсу
src/components/ui/   shadcn/ui з шаблону Lovable
src/styles.css       дизайн-система (oklch), зокрема токени допуску й типів сутностей
```
